# Recruiter-facing backend expansion contract

This increment prioritizes demonstrable correctness, operational safety, and explainable tradeoffs. It does not authorize deployment, real-data testing, remote migrations, or invented chapter policies.

## Increment

1. Test/migration target guards reject PostgreSQL URL query routing overrides. Synthetic fixture startup and shutdown clean up only records owned by that invocation.
2. New additive migration `002-security-audit.sql` adds event integer versions and an officer audit table. Never edit applied migrations 000/001.
3. Event edits require an expected version; competing edits cannot silently overwrite one another. Version comparison and increment happen under the existing event-row lock. Stale edits return HTTP 409 `STALE_EVENT`; the UI preserves the unsaved form and offers an explicit reload.
4. Successful event creation/edit, membership-status changes, first attendance recording, and CSV exports produce officer audit entries. Mutations and their audit entry commit together. No name, email, title, description, free-text payload, or ticket is logged. Metadata is explicitly selected statuses, counts, versions, and non-sensitive IDs. Request correlation IDs are generated by the server, not trusted from the client.
5. Audit history is officer-only, paginated, optionally filtered by a fixed action allowlist. No application endpoint updates or deletes audit records. This is application-level append-only history, not a cryptographically tamper-proof log; database administrators remain trusted. Production access and retention require a separate policy.

## Contracts and ownership

Main owns shared API types, route/validation integration, HTTP tests, acceptance and documentation. Backend Luna owns migration 002, platform service, and its PostgreSQL integration tests. After the two safety workstreams finish, a Luna UI worker owns the officer Activity view and stale-edit UI. No simultaneous overlapping writes.

`PlatformEvent.version` starts at 1. `EventInput` excludes it. PATCH event JSON adds `expectedVersion`; service `updateEvent(actor, id, input, expectedVersion)` rejects missing/invalid versions. `listAudit(actor, {page,pageSize,action?})` returns `Page<AuditEntry>`. `GET /api/platform/officer/audit` is officer-only. `Actor.requestId` is optional for direct service tests but always generated in HTTP handling; service-only calls generate a UUID fallback.

## Acceptance

Real PostgreSQL tests: competing same-version edits yield one success and one conflict; audit is atomic with writes; failures do not create success records; duplicate check-in doesn't duplicate audit; private data/tickets don't appear in audit; regular members cannot read it; filtering/pagination are bounded. Keep existing last-seat, ownership, CSRF, rollback, and date tests. Repeat lint/types/build and actual local browser review of changed UI.

Local backup/restore evidence is useful but not a production disaster-recovery guarantee. Threat model and residual risks belong in the final documentation. Resume claims stay limited to code and tests actually executed.
